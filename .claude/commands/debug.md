description: 体系的デバッグプロトコル — 再現→証拠収集→複数仮説→反証→修正→回帰テスト
argument-hint: [バグの症状・エラーメッセージ]
---
対象: $ARGUMENTS

思いつきでコードを書き換えるのではなく、以下のプロトコルで進めてください:

1. 再現: まず確実な再現手順を確立する。再現できないバグは直せない。
   再現がフレーキーなら頻度も記録する(10回中何回か)。
2. 証拠収集: ログ・スタックトレース・関連コードの調査は explorer サブエージェントに委譲し、
   要点だけを受け取る。生ログをメインコンテクストに流し込まない。
3. 仮説: 原因仮説を最低2つ立てる(1つしか浮かばないなら、それは思い込みの可能性が高い)。
   各仮説に「これが正しければ X が観測されるはず」という反証可能な予測をつける。
4. 判別: 予測を検証する最小の実験(ログ追加・最小再現コード・git bisect)で仮説を絞る。
   「以前は動いていた」系の回帰バグなら git bisect を第一候補にする。
5. 修正: 原因を特定してから修正する。「なぜ今まで動いていたのか / なぜ壊れたのか」を
   説明できないうちは修正しない(症状だけ消える修正は再発する)。
6. 回帰テスト: このバグを再現するテストを追加してから完了とする
   (修正前に失敗し、修正後に通ることを両方確認する)。
7. 3回修正に失敗したら停止する。状況(試したこと・観測結果・残る仮説)を整理し、
   architect サブエージェントに根本原因分析を依頼する。
